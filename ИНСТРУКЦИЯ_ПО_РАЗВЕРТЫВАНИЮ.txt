  (актуально на 23.08.2026)
================================================================

ЧТО В ПРОЕКТЕ
----------------------------------------------------------------
Dockerfile            — образ: nginx:alpine + nodejs (админ-бэкенд)
docker-compose.yml    — сервис web, порт 8080 -> 80, volume ./data
docker-entrypoint.sh  — запускает nginx и Node-бэкенд вместе
nginx/nginx.conf      — gzip, кэш, SPA-fallback, прокси /admin и /api/
public/               — сайт (index.html, assets/, правовые страницы)
server/admin-server.mjs — бэкенд: авторизация, контент, /api/news
server/admin/         — веб-панель /admin (HTML/CSS/JS)
deploy.sh             — скрипт деплоя (запускается НА VPS)
deploy.ps1            — скрипт деплоя с Windows-машины по SSH
.env.example          — шаблон секретов (скопировать в .env)
.gitignore            — не пускает в git секреты и мусор
data/                 — создаётся при первом запуске (volume):
                        content.json (правки админки), secret.key (сессия)

================================================================
ШАГ 1. ПОДГОТОВКА НА ЛОКАЛЬНОЙ МАШИНЕ (Windows)
================================================================

1.1. Убедитесь, что установлены:
   - Docker Desktop (https://www.docker.com/products/docker-desktop/)
   - Git (https://git-scm.com/downloads)

1.2. Создайте файл секретов .env (ОБЯЗАТЕЛЬНО):
   - скопируйте .env.example в .env
   - откройте .env и задайте СВОЙ надёжный пароль админки:

       ADMIN_USER=ta-admin
       ADMIN_PASS=ВашНовыйСложныйПароль

   Без .env сборка НЕ запустится — это защита от пароля по умолчанию,
   который считается скомпрометированным.

1.3. Локальная проверка (необязательно, но полезно):

       docker-compose build
       docker-compose up -d

   Затем откройте:
       http://localhost:8080          — сайт
       http://localhost:8080/admin/   — панель управления
       http://localhost:8080/healthz  — проверка живости (должно быть: ok)

================================================================
ШАГ 2. ЗАЛИВКА НА GITHUB
================================================================

2.1. Создайте ПРИВАТНЫЙ репозиторий на github.com:
   GitHub -> New repository -> Name: lastbot -> Private -> Create.

   Приватный — потому что в проекте есть логика админки.

2.2. Создайте SSH-ключ (если ещё нет) и добавьте его в GitHub:
   (GitHub -> Settings -> SSH and GPG keys -> New SSH key)

       ssh-keygen -t ed25519 -C "ваш@email"
       cat ~/.ssh/id_ed25519.pub   # содержимое вставить на GitHub

2.3. Из папки проекта выполните:

       git init
       git add .
       git commit -m "LASTBOT: сайт + админка + деплой"
       git branch -M main
       git remote add origin git@github.com:ВАШ-АККАУНТ/lastbot.git
       git push -u origin main

   Проверка: .gitignore уже исключает data/, .env, скриншоты и архив,
   поэтому git status после push должен быть чистым, а в репозитории
   НЕ должно быть файлов data/secret.key и .env.

================================================================
ШАГ 3. ПОДГОТОВКА VPS
================================================================

3.1. Подключитесь к серверу:   ssh root@IP_ВАШЕГО_СЕРВЕРА

3.2. Установите Docker и Docker Compose (Ubuntu/Debian):

       curl -fsSL https://get.docker.com | sh
       systemctl enable --now docker

   Проверка:  docker --version && docker compose version

3.3. Склонируйте репозиторий:

       git clone git@github.com:ВАШ-АККАУНТ/lastbot.git /opt/lastbot
       cd /opt/lastbot

3.4. Создайте .env на сервере (тот же пароль, что в шаге 1.2):

       cp .env.example .env
       nano .env        # задайте ADMIN_PASS

   БЫСТРЫЙ СПОСОБ (если .env уже создан на локальной машине):
   перешлите его на сервер и пропустите правку вручную —

       scp .env root@IP_ВАШЕГО_СЕРВЕРА:/opt/lastbot/.env

   (команда выполняется на локальной машине из папки проекта,
    затем на сервере останется только запустить ./deploy.sh)

3.5. Первый запуск:

       ./deploy.sh

   Скрипт сам сделает: git pull -> сборку образа -> перезапуск ->
   проверки /healthz и /api/news. В конце должны быть строки:
       healthz: ok
       /api/news: ok

3.6. Если сайт за Cloudflare: после первого деплоя и после каждого
   обновления сбрасывайте кэш: Cloudflare -> Caching -> Purge Everything.

================================================================
ШАГ 4. ОБЫЧНОЕ ОБНОВЛЕНИЕ САЙТА
================================================================

Вариант А — с Windows-машины (после правок в файлах):

    git add .
    git commit -m "описание правок"
    .\deploy.ps1 -Server root@IP_ВАШЕГО_СЕРВЕРА -Path /opt/lastbot

   deploy.ps1 сам запушит код и выполнит deploy.sh на сервере.

Вариант Б — прямо на VPS:

    cd /opt/lastbot
    ./deploy.sh

ВАЖНО про кэш браузеров:
   Статика (css/js) отдаётся с Cache-Control: public, immutable.
   При каждом изменении файлов в public/ поднимайте версию в index.html
   (и в terms.html, privacy.html, refund.html):
       ?v=2  ->  ?v=3  ->  ?v=4  ...
   Иначе посетители будут видеть старую версию до конца кэша.
   Плюс сбросьте кэш Cloudflare (пункт 3.6).

ШАГ 5. СМЕНА ПАРОЛЯ АДМИНКИ
================================================================

   Пароль задаётся ТОЛЬКО в файле .env на сервере:

       cd /opt/lastbot
       nano .env                # новый ADMIN_PASS
       ./deploy.sh              # перезапуск с новым паролем

   Альтернатива (для быстрой смены без полного деплоя):

       docker-compose down
       docker-compose up -d

================================================================

   curl http://localhost:8080/healthz            -> ok
   curl http://localhost:8080/api/news?lang=ru   -> JSON с новостями

================================================================
ТИПИЧНЫЕ ПРОБЛЕМЫ И РЕШЕНИЯ
================================================================

1) «Переключатель языка не работает» / сайт выглядит по-старому.
   Причина: браузер или Cloudflare держат старый main.js.
   Решение:
   - обновить файлы на сервере (git pull + deploy.sh);
   - поднять ?v= в index.html (см. ШАГ 4);
   - Purge Cache в Cloudflare;
   - в браузере: Ctrl+Shift+R или режим инкогнито.
   Проверка, что сервер отдаёт новое:
       curl -s https://ваш-домен/assets/js/main.js?v=2 | grep -c applyLanguage
   (результат должен быть больше 0)

2) «Failed to load resource: 403» от corsproxy.io.
   Старая версия сайта обращалась к сторонним CORS-прокси.
   Актуальная версия ходит только в свой /api/news.
   Решение: обновить файлы (см. п.1). Свежий main.js не содержит
   упоминаний corsproxy (проверка: grep -c corsproxy main.js -> 0).

3) «Вход выполнен, загружаю панель…» и панель не открывается.
   Решение: Ctrl+F5 или инкогнито-окно. Если под кнопкой красная
   надпись — прочитайте её: там точная причина (нет связи, код ответа).
   Если панель пустая совсем — проверьте логи: docker-compose logs -f web.

4) Новости показывают «Офлайн-режим».
   Значит /api/news не смог получить ленту Google News (сервер VPS
   может быть заблокирован Google). Сайт при этом работает — показывается
   резервный список постов VK. Это не ошибка кода.

5) Порт 8080 занят на VPS.
   В docker-compose.yml поменяйте левую часть: "8080:80" -> "80:80"
   (или другой порт), затем deploy.sh.

БЕЗОПАСНОСТЬ (ОБЯЗАТЕЛЬНО К ВЫПОЛНЕНИЮ)
================================================================

- Никогда не коммитьте data/ и .env (закрыто .gitignore).
- Пароль админки по умолчанию (142536Mainkey) СКОМПРОМЕТИРОВАН —
  смените до первого публичного запуска (ШАГ 1.2).
- Панель /admin доступна всем, кто знает адрес. Если хотите ограничить
  доступ по IP — добавьте в nginx.conf внутри location ^~ /admin:

      allow Ваш.IP.Адрес.0/24;
      deny all;

  и перезапустите контейнер.
