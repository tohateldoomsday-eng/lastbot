------------------------------------------------------------
2. АРХИТЕКТУРА
------------------------------------------------------------
Стек: статический сайт (HTML/CSS/ванильный JS) + Node-бэкенд
(чистый Node, БЕЗ внешних зависимостей) + Nginx. Продакшн — Docker.

- Nginx: отдаёт статику из public/, проксирует /api/* и /admin
  на Node-бэкенд (127.0.0.1:3000), gzip, кэш, SPA-fallback,
  security-заголовки. Конфиг: nginx/nginx.conf.
- Node-бэкенд: server/admin-server.mjs (порт 3000, слушает 127.0.0.1).
  Отвечает за: админ-панель /admin, API /api/*, авторизацию
  (HMAC-токен в httpOnly-куке lb_auth, 12 часов), хранение контента.
- Данные: папка data/ (volume в Docker, В GIT НЕ КОММИТИТСЯ):
  - content.json — весь контент сайта (создаётся при первом старте
    из дефолтов в admin-server.mjs, раздел DEFAULTS);
  - secret.key — секрет подписи сессии;
  - telegram-posted.json — список уже опубликованных в TG новостей.
- .env (в git НЕ коммитится; образец — .env.example):
  ADMIN_USER, ADMIN_PASS (без ADMIN_PASS сборка/запуск намеренно
  не стартует), BOT_TOKEN, TELEGRAM_CHANNEL=@lastbotdls.
- Локальный запуск БЕЗ Docker (для проверки):
  1) node server/admin-server.mjs  (порт 3000)
  2) node _check-server.mjs (временный файл в корне: отдаёт public/
     и проксирует /api, /admin на 3000; порт 8080).
  В продакшене _check-server.mjs НЕ используется.

3. СТРУКТУРА ФАЙЛОВ
------------------------------------------------------------
Корень:
- README.md — общая документация (сборка, деплой, админка).
- ИНСТРУКЦИЯ_ПО_РАЗВЕРТЫВАНИЮ.txt — пошаговая инструкция деплоя.
- Dockerfile, docker-compose.yml, docker-entrypoint.sh — контейнеризация.
- deploy.sh / deploy.ps1 — деплой на VPS (git pull → бэкап data/ →

- _check-server.mjs — временный локальный сервер для проверки

public/ (статический сайт):
- index.html — главная страница (все секции).

  (класс body="legal-page", robots noindex).

  счётчики, лента новостей, промокоды, гидрация контента.

server/:
- admin-server.mjs — Node-бэкенд (API + авторизация + DEFAULTS).
- admin/ — веб-панель /admin (index.html, admin.css, admin.js).

- telegram-bot.mjs — автопостинг новостей в TG-канал (каждые 4 часа).

4. КОНТЕНТНАЯ МОДЕЛЬ
------------------------------------------------------------
Контент хранится в data/content.json (правится через админку) и в
словаре i18n.js для не-русских языков. Ключи верхнего уровня:
- hero: badge, titleLine1, word1/2/3 (кинетические слова),
  subtitle, trust[] (3 пункта доверия).
- why: heading, sub, cards[] (4 карточки: title, text, label).
- features: heading, sub, items[] (6 модулей: tag, title, text).
  Порядок важен: items[0] — флагманская карта «Помощь альянсу».
- pricing: heading, sub, note, tiers[] (3 тарифа: name, bots, price
  в долларах, features[]).
- news: heading, sub, items[] (заголовки/даты/ссылки официальной ленты).
- codes: items[] (промокоды: code, reward, expires).
- faq: heading, items[] (q, a). Сейчас 7 вопросов.
- cta: heading, text.
- how: items[] (3 шага).
- contacts: email, telegramHandle, telegramUrl, tagline.
- dashboard: url (ссылка кнопки «Дашборд» в меню).
- ui: короткие строки интерфейса (кнопки, подписи, статы).

Гидрация (main.js):
- Для русского: /api/content (админ-контент) применяется поверх HTML.
- Для других языков: применяется словарь i18n.js.
- Селекторы привязки: .bento-item (по порядку), .price-card (по
  порядку), .why-grid .glass-card, .step, #features/#pricing/...
  заголовки, .cta-panel, .faq-list (полная перестройка), и т.д.
- ВАЖНО: при изменении ПОРЯДКА элементов в HTML нужно менять порядок
  в ТРЁХ местах: index.html, DEFAULTS в admin-server.mjs, словари
  всех 8 языков в i18n.js.

Промокоды: массив CODES в main.js — дефолт; перекрывается из
контента (админка) / словаря. Рендерятся в двух местах:
- вкладка «Промокоды» в секции новостей (#codesList),
- компактная панель в hero (#heroCodesList) с раскрывашкой
  «Как активировать промокод» (шаги codesHowStep1-3).

6. ТЕМЫ ОФОРМЛЕНИЯ
------------------------------------------------------------
- Две темы: тёмная (по умолчанию, брендовая) и светлая.
- Механизм: класс html.light; переменные CSS в :root (тёмная) и
  html.light (светлая). Светлая палитра: фон #eef2fa, панели белые,
  текст #0f172a, неон приглушён (cyan #0891b2, violet #7c3aed и т.д.).
- Переключатель: кнопка #themeToggle в шапке (луна/солнце).
  Выбор хранится в localStorage ("lb_theme": "light"|"dark").
  Дефолт: сохранённый выбор → системная тема (prefers-color-scheme)
  → тёмная. Анти-FOUC: инлайн-скрипт в <head> применяет тему
  до отрисовки (есть на всех 4 страницах).
- meta theme-color меняется вместе с темой (#05070f / #eef2fa).
- Админ-панель (server/admin) имеет СВОЮ тёмную тему — светлая тема
  сделана только для публичного сайта.

7. ЯЗЫКИ (i18n)
------------------------------------------------------------
8 языков: ru (дефолт), en, es, de, fr, pt, zh, ar (арабский — RTL,
есть [dir="rtl"] стили).
- Переключатель в шапке, выбор в localStorage ("lb_lang").
- Логика в main.js: applyLanguage → applyUI (строки ui.*),
  applyContent (контент). Русский берёт контент из админки,
  остальные — из словаря i18n.js.
- При добавлении новых ключей ui.* или секций контента нужно
  обновлять ВСЕ 8 языков в i18n.js + DEFAULTS в admin-server.mjs.

------------------------------------------------------------
8. API АДМИН-БЭКЕНДА
------------------------------------------------------------
- POST /api/login {u, p} → кука lb_auth (HMAC, 12 ч). Rate-limit:
  8 попыток за 10 минут. Без ADMIN_PASS → 503.
- POST /api/logout
- GET /api/content — публичный контент (JSON).
- PUT /api/content — сохранение (только авторизованным; мерж по
  верхним ключам).
- POST /api/content/reset — сброс к DEFAULTS.
- GET /api/news?lang=ru — RSS-лента Google News (белый список языков,
  SSRF-безопасно; кэш 15 мин).
- POST /api/telegram/post-news — ручной постинг в TG (авторизованным).
- GET /api/status — {ok, authed}.
- Статика админки: /admin, /admin/login, /admin/index.html и т.д.
- Админка: логин ta-admin, пароль из .env. В панели редактируются все
  секции контента; «Сохранить» публикует сразу; «Сбросить контент»
  возвращает заводские значения (DEFAULTS).

12. ДЕПЛОЙ (кратко)
------------------------------------------------------------
Требования: Docker 20.10+, git.
- Первая настройка VPS:
  git clone https://github.com/tohateldoomsday-eng/lastbot.git /opt/lastbot
  cd /opt/lastbot
  cp .env.example .env  → задать ADMIN_PASS (и BOT_TOKEN)
  ./deploy.sh
- Сайт: http://IP:8080, админка /admin/.
- Обновление: ./deploy.sh на сервере или
  .\deploy.ps1 -Server root@IP -Path /opt/lastbot с Windows.
- Локальная разработка без Docker: см. раздел 2 (node + _check-server.mjs).
